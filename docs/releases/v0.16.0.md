# Floptle v0.16.0 — "Frame by Frame"

One feature: **sprite sheets on materials**. A texture sliced into a grid, one
cell drawn on a mesh, the cell index animated at runtime — the thing UI images
have been able to do since v0.14.0, now available to anything with a surface.

## The case it exists for

A character's face on a plane. Sixteen expressions in one PNG, and the game picks
one per frame: talking, blinking, angry. The same shape covers an animated
billboard, a flipbook effect on a quad, a spinning coin, a readout panel on a
console.

Before this, the answer on a mesh was to write a `.flsl` shader that did the UV
arithmetic itself, or to keep one PNG per frame and swap `Material.texture`. Both
work. Neither is what "use a sprite sheet" should cost, and neither matched the
engine's own UI, where the same texture was already sliced, picked from a grid of
thumbnails, and animated on a track.

## Slice the texture once

The grid lives on the **texture**, in its asset settings — columns × rows, with
the cell preview it already had. Everything that uses that texture inherits the
same slicing: a HUD image, a mesh material, a per-face material on map geometry.
Re-slice the `.png` and every material using it re-slices with it (a cell that no
longer exists falls back into range rather than drawing off the end).

On the Material, that lands as three fields — `sheet_cols`, `sheet_rows`, `cell`
— and a **cell picker** under the texture row: the sheet drawn as a clickable grid
with the current cell ringed, which is literally the same widget the UI element
inspector uses. Same row-major order from the top-left, same ring, same hint.

## Animate the cell

```lua
local face, fps, frames, t = nil, 8, 16, 0

function start(node) face = node:getcomponent("Material") end

function update(node, dt)
  t = t + dt
  face.cell = math.floor(t * fps) % frames
end
```

`cell` is a live mirror field, which buys three things at once from one place:
the write above, `node:setMaterial{ cell = n }` for setup-time slicing, and a
**stepped property track** in the Animation tab (＋ Property ▸ Material ▸ cell) —
including record mode auto-keying it when you click a different cell with ● REC
on. `sheetCols` / `sheetRows` are writable too, for the rare script that slices
its own texture.

## Why this needed no shader and no new instance lane

A sheet cell is a **UV window**, and materials have carried a UV transform since
v0.7.0 — the tiling block. So a sheet material packs its cell as that transform
(`Material::effective_tiling`), and everything downstream inherits it for free:
the built-in look, the depth/shadow paths, and a custom `.flsl`'s `baseTexture()`,
which now honours the cell without knowing sheets exist.

This mattered because the raster instance stream is **full** — 16 of 16 vertex
attributes, the last one being the tiling lanes. A "sheet" attribute would have
meant a format change; a cell window meant none.

The arithmetic is the part worth being careful about: the renderer scales UVs
about the 0.5 **centre** before adding the offset, so a cell's offset is its own
centre minus that one, not its corner. Corner-based offsets look right for the
middle of a sheet and wrong everywhere else, which is exactly the failure the new
`sprite_sheet_probe` catches — four quads showing cells 0, 3, 5 and 15 of a 4×4
sheet, asserted per cell at the centre *and* at four edge samples, next to a
control quad drawing the un-sliced texture so a flat pass can't be a vacuous one.

## Also true of it

- **A sheet wins over a tiling block.** Repeating or rotating one cell would drag
  in its neighbours, which is never the intent — the same rule UI images follow.
  The Inspector says so where the tiling rows would be, rather than leaving
  controls that quietly do nothing.
- **Use the Pixelated filter for pixel art.** A smooth filter can pull half a
  texel from the neighbouring cell at a seam. This is a property of sampling a
  grid, not of this implementation, and it applies to UI images equally.
- **Cells clamp.** Walking past the last frame shows the last frame.
- **Raster surfaces only** — meshes, primitives, map geometry, per-face
  materials. Blobs and SDF matter have no UVs to window.
- **The packing moved into the renderer.** `MaterialParams::from_material` is now
  the single conversion from an artist-facing material to instance params, shared
  by the editor's gather and the probes — so a probe can't pass against code the
  editor doesn't draw with.

## Upgrading

Purely additive. A material that isn't a sheet serialises exactly as before (the
three fields skip-serialize at zero, so no existing `.ron` changes), pre-sheet
material files load unchanged, and no wire protocol or script behaviour moved.
**1237 tests**, workspace clippy clean.
