# Floptle v0.14.0 — "House Style"

The complaint this release answers, in the words it was made in: *"it's
genuinely really hard to get UI that looks good and not sloppy or AI
generated."*

That is not a shortage of widgets. The engine already drew rectangles and text.
What it had no way to express was **"these forty things are the same kind of
thing"** — so every screen was forty independent rectangles, each one hand-placed
and hand-coloured, each one free to drift a pixel and a shade away from its
neighbours. Sloppy is what that looks like from across the room.

So the unit of work here is not the button. It is the **style**: a named look,
defined once in a file, worn by every element that asks for it, with the five
interaction states and the transitions between them included. Change the file,
change every screen.

## The engine still has no opinion about your game's look

Stated up front because it constrained every decision below. There is **no
built-in focus ring, no built-in scrollbar, no drag ghost, no tooltip drawn by
the engine, and no default theme.** Floptle ships zero styles. A "widget" is your
own elements: a scrollbar is a track element with a `part: Handle` child, focus
is whatever your style's `focus` block says it is, a tooltip is an element you
designed. Anything the engine drew for you would be the engine choosing a look
for your game, and a horror game and a puzzle game do not want the same one.

Where a default was unavoidable, it derives from *your* project: the UI tab's
snap step is your smallest spacing token, not 8 px. Editor chrome uses the
editor's palette, never your accent colour — which would vanish the day someone
designs in that colour.

## Tokens, then styles

`*.tokens.ron` names the values: colours, a spacing scale, radii, a type scale,
fonts. `*.uistyle.ron` names the looks, referring to tokens rather than numbers.
Both are merged from anywhere in the project and hot-reload on save — edit a
token, watch every screen in the game repaint.

A style has a `base` block and up to five state blocks (`hover`, `pressed`,
`disabled`, `focus`, `selected`) with a fixed precedence, plus one transition
(duration + easing, 8 curves) that every animatable property rides.

Two rules keep this from becoming CSS:

1. **One style per element.** No cascade, no specificity, no `!important`, no
   wondering which of four rules won.
2. **A property the style doesn't mention is left exactly as you authored it.**
   Styles set what they say and nothing else, so a style is safe to apply to an
   element you already positioned.

## The paint box

Styles are only worth having if there is something worth styling. Elements gained
gradients (linear, plus centre-origin radial and angular), per-corner radii,
per-side borders, inset shadows, glow, film grain, four blend modes, 9-slice
borders, image tiling/offset/fit, layout-neutral rotate and scale about a pivot,
cascading opacity and tint, and text stroke / shadow / tracking / line-height /
wrapping / max-lines / ellipsis / case.

## ◫ A tab for designing screens

The canvas is the **real GPU pipeline** rendering into an offscreen target — not
an approximation of your UI, your UI. Rulers and guides, snapping (guides beat
siblings beat grid) with smart-guide lines, align and distribute, marquee
multi-select, resize grips, nudge, drag-to-reorder inside a stack with an
insertion caret, inline text editing, forced state preview, an outline panel with
depth dragging and visibility/lock, copy/paste style, and **"make this a style"**
for when you've designed something by hand and want it named.

The multi-resolution preview **re-solves** the layer rather than scaling a
picture of it, which is the only version of that feature that tells you anything.

## Things that are yours now, not the engine's

- **Focus and directional navigation.** Spatial nearest-ahead with a cross-axis
  penalty so a column walks down itself, per-layer wrap and repeat timings, name
  overrides where the geometry guesses wrong, and a nav-graph overlay in the UI
  tab. Submit fires the **same** `clicked` a mouse fires, so nothing has to be
  written twice.
- **Toggles and radio groups**, layer-scoped.
- **Real scrolling** on two axes, with drag-to-pan, and scrollbars made of your
  own elements.
- **Text fields** — caret, selection, clipboard, OS key repeat, character (not
  byte) length caps, numeric / upper / masked modes, placeholder, `changed` and
  `submitted`. Implicitly focusable, and they own Left/Right while focused.
- **Drag and drop** — `draggable` and `drop_target`, with `ui.dragging()`. No
  payload channel, deliberately: the thing being dragged is a node, and a node
  already carries params, name and tags.
- **Tooltips** — a string on any element, and one `tooltip_box` element per layer
  that you design.

## Lua

- `color(r,g,b[,a])`, `color.hex("#rrggbb")`, `color.lerp(a,b,t)` — a plain
  `{r,g,b,a}` table, and component colour fields read and write as whole colours.
- `ui.bind(node, prop, fn)` — the property follows the function, evaluated after
  `update`. The component is chosen by which one *has* that field, so `"value"`
  finds the slider without being told.
- `repeater` — a prefab per row against a count; the engine spawns and destroys
  the **difference**, and each row reads `node.index`.
- `input.typed()` — this frame's characters, resolved by the OS keyboard layout,
  with paste folded in. This closes **floptle/0035**: polling `a`–`z` was getting
  three lobby codes in four wrong, because eight of the relay's thirty-two
  symbols are digits.

## A demo you can open

`assets/scenes/ui_demo.ron` — press Play. Every mechanism above on one screen,
with a walkthrough in [docs/ui-demo.md](../ui-demo.md).

Two things it is built to prove. **Delete the two files in `assets/ui/` and it
still runs** — grey, flat, and completely functional; the entire look lives in
those files. And the Lua behind it is about **110 lines across five files**, with
no layout arithmetic, no hover functions, no list rebuilding and no key polling.
The tab strip and the toggle chips have no script at all.

## Netcode

Three reports from a game being built on the engine, closed:

- **floptle/0048 — a client could not point its own fighter.** Two faults. The
  client-side setup runs before `RollbackStart`, so every driven node landed in
  the filter that gates *every* pass including `lateUpdate`, which no driver
  replays. And the interpolation guard asked `Session::rollback` — a second
  answer to "is this node locally driven" that can disagree with the driver
  itself. The driver now publishes its own node set, and a sample that slips past
  the guard is counted and named in the Console.
- **floptle/0049 — the input delay is choosable.** `net.host{ inputDelay = n }`
  and `net.setInputDelay(n)`; with neither, the host derives it from measured RTT
  (2 on a LAN, 5 at 112 ms). The 🌐 panel puts delay and mispredict rate on one
  line, because neither number means anything alone.
- **floptle/0050 — a replay determinism audit**, on by default in the editor. The
  proposed cheap check does not work and we said so: hashing a correction's
  replayed ticks against their originals compares nothing, because the correction
  changes an input and the state legitimately differs from that tick onward. This
  is a **second replay** with provably identical inputs from the same anchor —
  same inputs, same anchor, same code, so any difference is a value the sim reads
  that `snapshot()` doesn't carry. It reports locally and names the field.

## Things that would have shipped broken

The demo was built to be shown, and showing it is what found these.

- **The mouse was offset from the cursor.** Three places built a layer's element
  tree — the hit test, the screen overlay, the world canvases — and only the
  overlay applied styles. Since styles set padding, gap and text size, the hit
  test was solving a layout that had never been on screen: 22 design units out on
  the demo's buttons, 58 at worst, ~87 physical pixels at 1080p. Building a tree
  is one function now, and it cannot return an unstyled one.
- **…and worse in a docked editor.** `game_view()` answers "does the Game tab
  have focus", and every pointer conversion was asking it as if it answered
  "where is the game drawn". A docked tab is both, so the pointer was measured
  against the whole window while the game rendered into a panel a third that
  size, with the error growing across the screen. "Where are the pixels" is its
  own predicate now, and the render path, the script view info, the gizmo
  projection and the hit test all ask it.
- **Clicking the Inspector pressed game UI behind it**, and a context menu
  floating over the Game view was clicked *through*. The pointer is bounds-checked
  and layer-checked now. Keyboard focus is unaffected, so a menu doesn't stop the
  game reading keys.
- **`node:uiRect()` documented "the same space as `input.mouse()`" and returned a
  different one.** Window space now, like `input.mouse()`,
  `camera.worldToScreen()` and `camera.screenToRay()`.
- **A world-space canvas was invisible in the docked Game tab and still
  clickable** — that view never drew any UI into the world. Both views call one
  function now.
- **Clicking into a long text field put the caret a word or two from the
  pointer.** A value wider than its box scrolls to keep the caret in view, and
  the click-to-caret mapping never undid that scroll. The formula lives in one
  place, tested including the round trip: the x a caret is *drawn* at must map
  back to that caret's own index.
- **`Tokens.radii` was defined and unreachable**, and shadow and glow colours
  could not be tokens. Found by building the demo, which is what demos are for.
- **Booleans in Lua were 1/0**, and `0` is truthy, so `if el.visible then` was
  always taken. This is the one non-additive change in the release — see
  Upgrading.

## Upgrading

No file format changed and the wire protocol is untouched; every existing project
opens as before, and 393 UI elements across two real projects round-trip without
gaining a key.

**One behaviour change.** Boolean component fields now read back from Lua as
booleans instead of `1`/`0`. If a script compares one numerically — `if
rb.lockY > 0 then` — change it to `if rb.lockY then`. Neither of the projects
built on the engine did this; the engine's own rigidbody test did, which says how
easy the trap was.
