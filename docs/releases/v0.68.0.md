# Floptle v0.68.0 — "It Has To Be Clickable"

Three things a package could not ask the editor, so it had to guess — and two of
the guesses had shipped as visible bugs.

## Does this icon actually draw?

`gui.hasGlyph(text)` — whether every character in a string has an outline in the
editor's fonts.

A glyph no bundled font has renders as an **empty box**, and nothing warns you.
The character sits in your source looking perfectly fine, and the button looks
broken to whoever opens the editor. There has been no way to tell the two apart
without shipping it and looking.

```lua
local CLEAR = gui.hasGlyph("✖") and "✖" or "clear"
```

Two that look interchangeable and are not: on the bundled fonts `✕` (U+2715) and
`✓` (U+2713) do **not** draw. `✖` (U+2716) and `✔` (U+2714) do.

## A painted control can be hit-tested where it is about to be drawn

`gui.mouse().inside` used to mean "inside the part of the panel already drawn".
That is the wrong question by construction: a package testing whether the pointer
is over a control asks *before* drawing it, so the pointer sat over a region that
did not exist yet and the answer was always no.

The effect was a painted button that could not be clicked — most often one at the
right-hand end of a row, where nothing had been drawn yet. Its geometry was
right; the check in front of it was not. `inside` now means "over the area this
layout can draw into", which is what it is asked at that moment.

The pointer contract is written down for the first time, too: `mouse()` is in the
same coordinates the painting calls take, you hit-test **before** reserving
space, and you reserve afterwards — a control drawn underneath something else
cannot be clicked however correct its geometry.

## A tool can read any node, not just the selected one

`scene.docs(ids, done)` gives the full document of any nodes, however many,
without touching your selection.

`scene.doc` reads what is selected, which is right for a tool acting on a
handful of things and wrong as the only way in. Renaming across a level,
collecting every user-facing string, proposing a reorganisation — all of them
have to read nodes nobody has selected, and selecting them first is an edit made
to somebody's selection in order to perform a read.

```lua
scene.docs(scene.all(), function(docs, missing)
    for id, doc in pairs(docs) do … end
end)
```

The callback also gets the ids that had no node, rather than quietly returning a
shorter list — which is how a tool reports renaming forty things having renamed
thirty-eight.

## Panels stopped widening themselves

A panel using `gui.flexibleSpace()` to push something to the right-hand end of a
row grew a little wider every frame, on its own, until it was the width of the
screen — and never came back.

The spacer claimed all the space that was left, so whatever came after it landed
past the right edge; the editor read that overflow as the size the panel wanted,
and a panel's remembered size only ever grows. It now takes the room left *after*
what follows it.

`gui.rightAligned(fn)` is the exact version for a row whose trailing content
changes width — a count, a status, a time. It lays out from the right edge, so
there is nothing to measure and nothing to be a frame behind. The contents read
back to front: the first thing you add sits furthest right.

## Upgrading

Nothing to do. `gui.hasGlyph`, `scene.docs` and `gui.rightAligned` are new, and
the two fixes only change behaviour that was wrong.

If you have been working around a self-widening panel by pinning its size, you
can stop.
