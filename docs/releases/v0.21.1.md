# Floptle v0.21.1 — "Which Key"

Four fixes, and one of them had been wrong for a year.

## `input.pressed("f9")` was always false

Not "sometimes". **No function key has ever reached a script.** Nor a numpad
key, a bracket, Home, PageDown or a backtick — the raw-key table the `input`
API reads stopped at the arrow keys, so a script asking about any of them got
the same answer as a script asking about a key nobody pressed.

The same key was bindable in Project Settings the whole time, because that path
went through a *different* table which has had the full set since v0.8.0. Two
tables answering one question is how a gap like that survives; there is one now,
and the raw name is derived from the bindable one.

The test that should have caught it enumerated only keys both tables already
had. It now checks the families that were missing.

## A lint for the hook signature that quietly kills a script

```lua
function update(dt)     -- ✖ `dt` is the NODE
```

Every lifecycle hook is called with the node first. Write `update(dt)` and Lua
binds the node to `dt`, and the first piece of arithmetic that touches it raises
— every frame, before anything visible has happened. From the outside that is
not an error, it is a script that does nothing at all, which is a much harder
thing to go looking for.

The warnings strip now says so, and names the signature to write instead.

## The Hub signs in again

The Hub persists the sign-in server it uses, and installs that had ever signed
in were carrying `dev-auth.fopull.com` — the Phase-1 dev instance, retired since
the provider moved to production. So sign-in answered `502`, and shipping a new
default would have fixed it for nobody: the value that overrides the default is
exactly what those installs have.

It is now treated as a **known-dead value** and rewritten on load. Anything else
you chose is still yours — a `localhost` dev provider is a supported target.

The session that host left behind is dropped too. It names an account that only
exists in a database that is gone, so it can only ever `401`; a window that
shows your name and then fails at everything is worse than a sign-in button. A
token we cannot read stays signed in, though — the refresh path already handles
a dead session, and signing somebody out over an unparseable field is the worse
of the two mistakes.

## The Hub tells you what a release was

The Installs tab used to show a version, a date and an Install button, which
tells somebody deciding whether to upgrade precisely nothing. Now it is a list
of versions and, beside it, **that release's notes** — the same
`docs/releases/vX.Y.Z.md` you are reading, rendered.

They travel *in* `releases.json`, embedded at publish time. One fetch buys the
whole history offline, including the versions already on your disk and the ones
published long before this existed — the publish step fills every entry it has
notes for, so the back catalogue populates itself. The GitHub release page gets
the same file, instead of "Automated release v0.21.0".

There is a `#[ignore]`d test that renders the tab to a PNG. A layout that was
only reasoned about is a layout that was not checked.

## Upgrading

Additive, with one behaviour change worth naming: keys that never worked now
work. If a script polls `input.pressed` for a key it could not previously see,
it will start seeing it.

`cargo test --workspace` and `cargo clippy --workspace --all-targets` are both
clean.
