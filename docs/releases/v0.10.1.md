# Floptle v0.10.1

Two fixes that stand between v0.10.0's rollback netcode and two people actually
playing over it. Both were found by a game being built on the release — an
arcade fighter that got as far as a working front end and then couldn't seat a
second player.

**Wire protocol is unchanged (still 11)**, so this interoperates with 0.10.0.
Update both machines anyway: the first fix is local to whichever peer joined.

## A joiner can play

"Slot" meant two unrelated things, and the driver used the wrong one:

- The **roster slot** is which fighter a peer drives — host 0, joiners 1+. It's
  the identity the input travels under, and it's the same on every machine, so
  that fighter #2 is fighter #2 everywhere.
- The **device slot** is whose keyboard and which gamepad the input is read
  *from*, and which per-player bindings apply.

On a couch these are the same number and everything works by coincidence. Over
a network they diverge: a joiner is roster slot 1, but they're sitting alone at
their own machine as *its* player one. Sampled by roster slot, they were handed
the couch's player-two layout and their own keyboard drove nothing at all.

This could only ever break for the person who joined. The host's roster slot is
0 and its device slot is 0, so the two agree for exactly one peer in the
session — the one the developer is sitting at.

Local input is now read from the device slot and still applied to the roster
slot, which was already correct: `set_tick_state` uses that slot's facing and
history. A practical consequence worth knowing: **a project needs no separate
binding set for joiners.** The same controls work whether you're player one or
player two.

The gamepad half of the original report turned out narrower than filed, and the
three behaviours are now pinned by tests because the spellings look
interchangeable in the Input settings and aren't:

| Binding | Behaviour |
|---|---|
| `Pad(id: Any)`, one pad connected | Falls back to the connected pad — always worked |
| `Pad(id: Any)`, **two** pads connected | Read the wrong one; fixed |
| `Pad(id: Slot(n))` | Names a pad outright, never consults the slot — unaffected |

## `net.lobbyCode()`

A game that asked for a relay session had no way to tell its own players the
code. The 🌐 panel had it and Lua didn't, so every game shipping its own lobby
screen had to send players into an engine debug panel to find out how their
friends were supposed to join.

```lua
function update(node, dt)
  local code = net.lobbyCode()
  find("CodeLabel").text = code or "getting a code…"
end
```

**Poll it rather than reading it once** — it's `nil` until the relay answers, a
round trip after `net.host{relay=…}`. It's `nil` for good on a client, and on a
direct/LAN host where there is no code and joiners use the address.

See [docs/multiplayer.md §5](../multiplayer.md).
