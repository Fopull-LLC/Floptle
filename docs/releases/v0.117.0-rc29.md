# Floptle v0.117.0-rc29 — "Whole Worlds" (beta)

Everything in rc28, plus a fix for planets that drew as one flat colour, and
the floating origin distance as a project setting.

## Terrain drawn in the wrong colour

A game that destroyed a terrain during play could leave every other terrain
drawn in a flat colour: the sand or teal of whatever node was made next. It
varied from run to run, and day, night and weather made no difference.

- A terrain destroyed during play is forgotten everywhere, as it already was
  in the editor.
- A reference to a destroyed node now finds nothing, where it could find the
  next node to be made.
- Each terrain draws with its own Material. One without a Material uses the
  active terrain's, and otherwise the same terrain's every run.

## Floating origin distance

**Project Settings → Game → Floating origin distance** (`origin_rebase_m` in
`project.ron`) sets how far the camera may get from the physics' origin
before the origin moves to it. Physics positions are finest near the origin:
4 km out they move in steps of about 0.25 mm. A shorter distance keeps what is
near the camera finer, and moves the origin more often. Each move shifts
every body by a whole number of metres, exactly, so nothing jumps. The
default stays 4,096 m.

## Upgrading

Nothing to do. What you may notice:

- A project with several terrains, only some of which have a Material, now
  draws each terrain that has one with its own.
- Code that kept a node after destroying it and read it later now gets
  nothing back, rather than the node made in its place.
