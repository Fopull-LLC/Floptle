# Floptle v0.10.3

The first real two-machine rollback match froze on ROUND ONE, on both screens,
with a clean console on each. This release is what was wrong.

> ⚠ **The wire protocol went from 11 to 12.** Builds refuse mismatched versions
> at connect, so every machine in a session — and the dedicated server, if you
> run one — needs this version. There is no partial upgrade.

## The redundant window wasn't redundant

A rollback session never retransmits anything. A retransmit would arrive after
the tick it was needed for, so instead every packet re-carries the last several
ticks: an input goes missing only if *every* packet carrying it drops. That is
the whole loss strategy, and it rests on one guarantee —

> an unconfirmed tick rides every packet until every peer has it.

The implementation didn't provide it. One FIFO held "the last N inputs admitted
from anybody" and did two unrelated jobs out of it: the duplicate filter, and
the fan-out payload. It was capped across all peers together, and it evicted
from the front.

Both halves of that are wrong, and both only bite in a real match:

- **Peers crowded each other out.** Every peer re-sends its window every tick —
  that being the point — so one peer's traffic evicted *another peer's* oldest
  entries.
- **The front is exactly what matters.** A starved peer is waiting on the oldest
  tick it is missing. Evicting from the front drops precisely the tick somebody
  is blocked on.

So: one lost datagram early in a match, and that tick was gone for good. The
client could never confirm it, so it stopped sending; so the host's frontier
froze; so the host stalled too. Two frozen screens, permanently, and nothing
anywhere to say which side had stopped receiving. The failure needs a lost
packet and a peer that falls behind — which is to say it needs a real network,
which is why every layer test passed. Tests pump both peers in lockstep from
tick 0 and never leave anybody behind.

The fix is structural, not a bigger cap:

- **One ring per peer.** Crowding stops being possible rather than becoming
  unlikely.
- **Retention floored by the minimum reported frontier.** Peers now report their
  rollback frontier on the `Input` message they already send every tick. This is
  the load-bearing part: the host's own frontier says *"I have everyone's input
  for T"*, which is a different claim from *"everyone HAS everyone's input for
  T"*, and dropping on the former is the bug.
- **The fan-out takes from the front.** The tick somebody is blocked on is in
  every packet until they say they have it.

## A frozen match now names itself

The above cost a replay-file autopsy to find. It should have cost a glance.

The 🌐 panel gained a frontier readout — `confirmed C of S simulated (N ahead)`
— and, per peer, what that peer has confirmed and how many of its inputs the
host is still holding. **A peer whose frontier has stopped moving while its held
count climbs is the starved one**, and the line turns orange when it happens.

A match stalled for more than a second also says so in the Console, on every
machine, once a second, naming every frontier it knows. So a two-machine test
no longer needs somebody watching a panel to learn which end broke.

## Fighters that nothing was running

The other half of the field report. A `Rollback` node's scripts sat un-ticked
for an entire match — every cross-script call into them answering `nil`,
hundreds of times a second, with no error to explain it.

`net_rollback_start` takes the running driver, rebinds it against the current
world, and abandons it when there is nothing to bind (a scene with no `Rollback`
nodes, or Play not started yet). Each of those paths dropped the driver **with
its node ids still in the script filters** — so the driver no longer ran them
and the global passes still refused to. Nothing ran them, silently, for the rest
of the session.

The filters (and the physics bodies) are now handed back before anything can
abandon the driver, and re-taken only once one is actually installed. On top of
that:

- **A match that binds nothing says so.** "A rollback match was announced but
  this scene has no Rollback nodes here" — because the alternative is a machine
  that stands still while the others fight.
- **A node nothing runs is an error, not silence.** Once per session the engine
  checks that every `Rollback` node is being run by *something* — the driver or
  the global passes — and reports it loudly as an engine fault if neither is.

## A warning that was wrong at the worst moment

Starting a match printed *"Player1 is a Rollback node but none of its scripts
define snapshot()/restore()"* about a script that defines both.

The audit ran inside `rebind`, which happens on the same frame as the scene
switch — a frame or more before the new scene's script environments exist. Ask
then and every answer is "no": no `snapshot`, no `restore`, no `synced`, because
there is nothing to ask. A warning that is wrong at exactly the moment somebody
is debugging is worse than no warning.

The script-level audit is now deferred until the environments are built, and
runs once, when the answer becomes knowable. The scene-level check (player slots
versus fighter count) still runs immediately — that one is answerable from scene
data.

## The referee was running a frame nobody else ran

`ShadowSim::build` ran one unfiltered script pass to construct the environments,
which also fired a full `start` + `update` on every fighter at t = 0 — a frame
the live session never runs, because it filters its fighters out before the
first pass. Any fighter script with state in `update` therefore made the referee
disagree with every honest peer by construction.

A referee that is wrong on purpose is worse than no referee; its entire job is
to be the one simulation nobody can argue with. The fighters are now filtered
out before that pass, exactly as they are live: environments get built, no
gameplay frame gets run, and `start` fires on tick 1 from the driver.

## Also

  predicted path → scene switch → match). The transport turned out to be
  innocent here, which is the point of keeping it: next time the symptom looks
