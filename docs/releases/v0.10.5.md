# Floptle v0.10.5

**The referee was running the match in freefall.** Every online match died at
its first checksum, half a second in, with both players told they had desynced.
Wire protocol unchanged (12) — this interoperates with 0.10.3 and 0.10.4.

## The referee's physics were not the game's physics

`ShadowSim::build` — the referee and match replays — built its `Sim` like this:

```rust
Sim::build(&world, &[], GravityField::uniform(Vec3::ZERO), DVec3::ZERO)
```

No gravity. No static colliders. No layers. No terrain. Meanwhile the live
session builds its `Sim` from the scene's real gravity field, its collision
layers, its terrain volumes and every `Collidable` in it.

So the referee ran the match with the fighters falling through an empty void
while both players stood on a stage. The state checksum hashes body position and
velocity, so the two could not agree past the first tick — and the **referee is
the sole judge** when one is running. At tick 30, the first checksum, it ruled
both players out of sync. The game ends a match on `net.on("desync")`, which is
why it read as an instant disconnect.

That default is a *test* convenience and always was. It shipped as the referee's
physics. The referee and the replay now take the live session's own `Sim`,
through `ShadowSim::build_with` and a new `Editor::build_sim_for_world` that is
`build_play_sim` pointed at another world — same gravity, same layers, same
terrain, same static colliders. Identity by construction, which is the shadow's
only claim to authority.

## Every test in that module was comparing two empty worlds

This is the part worth reading, because it is why two referee faults shipped in
two days.

`floptle_scene::to_doc` serializes `world.query::<Matter>()` — an entity without
a `Matter` component is not written to the document at all. The shadow tests'
fixture scene built entities with `Name`, `Transform`, `RigidBody`, `Replicated`
and `Scripts` — and no `Matter`. So **every document it produced was empty**.
Every shadow bound zero nodes. `fingerprint()` returned `""`. And every test in
the module compared one empty string to another, and passed.

That is how "a replay is the match, run again" was asserted for a feature nobody
had ever actually replayed. Both v0.10.3's build-pass fault and this one went
through that hole.

The fixture has `Matter` now, and a new test — `ring_is_not_hollow` — asserts
the document has nodes, that a shadow built from it binds them, and that the
fingerprint has content. The other tests in the module were run for real for the
first time and all still pass, which is at least a good sign about the rest.

`a_referee_agrees_with_a_live_driver_under_real_gravity` is the direct guard: it
runs a live `RollbackDriver` and a `ShadowSim` over the same log with the same
non-trivial physics and requires identical state hashes — **with a negative
control** asserting a referee on the wrong physics disagrees, so the test cannot
pass by the physics not mattering.

## A referee that disagrees with everyone is the one that's wrong

The deeper problem is that a wrong referee could end matches at all.

The referee is the sole judge on purpose: a quorum of players might all be
running the same modified build, so majority rule is not an anti-cheat. But a
cheat changes **one** machine, while an engine or content fault in the referee
changes **only the referee**. "Every peer disagrees with the referee, and they
all agree with each other" is overwhelmingly the second case.

Verdicts now wait until every peer has reported for a tick, and that case is
called what it is: the Console names the referee as the outlier, no desync is
raised, and the match carries on. A single peer out of step is still judged
against the referee exactly as before — the anti-cheat property is unchanged.

```
⚖ REFEREE disagrees with EVERY peer at tick 30, while the peers all agree with
  each other — so the referee is the one that is wrong, not the match.
```
