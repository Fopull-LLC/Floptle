# Floptle v0.43.0 — "Made of Something"

Surfaces stop being flat colours. There are slots for a normal map, a roughness
map, a metallic map and an occlusion map; a second lighting model that works out
the highlight from the surface instead of asking you to dial it in; and a set of
deliberate PS1-era artefacts for going the other way entirely.

Underneath, the whole scene now renders in real light — a lamp can be ten times
brighter than white and stay that way until the very last step, where you choose
how it lands on the screen.

And a long-standing bug is gone: most of the built-in shapes were lit inside
out.

---

## Lights can be brighter than white

Until now the scene was drawn straight into an 8-bit image, so nothing could be
brighter than white. A sunlit wall and a light bulb ten times brighter stored as
the same pixel. Bloom couldn't tell them apart, an exposure slider had nothing
left to recover, and a very bright colour didn't just go white — it went
*strange*, because each channel clipped on its own and the colour slid toward
whichever one clipped last.

The scene is now drawn in floating point and stays in real light all the way
through depth of field, denoise, grading, bloom, the lens and the sharpen. One
step at the very end brings it down to the screen, and **you choose which**:

- **clip** — clamp each channel. The default, and unchanged behaviour. It is
  also the right answer for flat 2D and pixel art, where every colour was
  authored inside the range already and a curve over it is a filter nobody
  asked for.
- **Reinhard** — never clips. Everything bright washes gently toward grey.
- **ACES** — the filmic curve: crushed shadows, a long warm highlight roll-off.
  Contrasty and confident.
- **AgX** — bright colours *whiten* as they climb, the way film and a camera
  sensor do. A very bright blue light reads as a bright light instead of a flat
  block of blue.

It's at the top of the Post Processing node, above the colour grade, because the
grade below it works in the range this choice defines. From a script:
`getcomponent("PostProcess").tonemap = 3`.

Try **AgX** on any scene with strong coloured lighting — it's the one that
changes the most.

**Nothing to do on upgrade.** The default is clip, which is exactly what the
engine did before, so no existing scene looks different until you pick one.

## Where the normal map goes

Open a Material and there is a **Surface maps** section:

- **normal** — bumps, bricks, panel lines, stitching, without the geometry.
  A **strength** slider scales the effect; drag it **negative** and every dent
  becomes a bump again, which is the one-click fix for a map authored the other
  way round.
- **occlusion** — baked contact shadows, read from the red channel. It darkens
  ambient and indirect light and never the key light, so it deepens crevices
  instead of greying the whole surface.

Both work under either lighting model, because they describe the surface rather
than the shading.

**They need nothing from the model.** No tangents to generate, no import
setting, no re-export. A normal map works on terrain you sculpted, on a cube, on
something you built with the Model tool, on a tilemap and on an animated
character, because the surface direction is worked out per pixel from what is
actually on screen.

## A second lighting model

Materials now choose between two, and neither is the degraded version of the
other:

**Classic (Blinn-Phong)** — what every material has always used. A specular
colour, a shininess exponent and a strength, all set by hand. Every existing
material is this, and nothing about it has changed.

**Physical (metal-rough)** — set **roughness** and **metallic** and the
highlight follows:

- **roughness** 0 is a mirror, 1 is chalk. The same light lands in a tight
  bright spot or a broad soft sheen.
- **metallic** 0 is a dielectric — plastic, wood, stone, paint: a white
  highlight sitting over a coloured surface. 1 is metal: no diffuse at all, and
  the highlight takes the surface's own colour, so a red metal has a red
  reflection. Values in between are a transition, not a material.

Each has a map slot. Roughness reads the **green** channel and metallic the
**blue** — the same layout glTF packs — so an occlusion/roughness/metallic image
exported from Blender or Substance drops into all three slots and does the right
thing.

A stylised surface wants a highlight you place; a realistic one wants a
highlight that falls out of the material. Pick per material.

## Retro artefacts, on purpose

A **Retro artefacts** section on every material, all off by default, each one
independent:

- **vertex jitter** — snap vertices to a screen grid, the way hardware with no
  fractional vertex coordinates did. Geometry near the camera wobbles between
  cells as it moves. Lower numbers are chunkier.
- **affine UVs** — skip perspective correction, for the era's warping, swimming
  textures on floors and long walls.
- **vertex lighting** — light per vertex instead of per pixel. Faceted
  highlights that slide across a face as it turns. A vertex-lit surface takes no
  shadows and no normal map, which is the point.
- **dither alpha** — screen-door transparency: partial opacity drawn as a
  pattern of solid pixels instead of blending. It never needs sorting, so it
  never shows the sky through the wall behind it.

Mix them with the maps above however you like. A wall can affine-map its texture
without jittering; a character can jitter and still take a normal map.

## A model's own materials, on the model

Select an imported model and the Inspector now lists **the materials it came
with** — every part, its name, its colour, whether it carries a texture — with an
**override** button on each. Overriding gives that one part its own material,
starting from the colour it already had, and never touches the model file.

Before this, the list was only visible by selecting the model in the Assets
panel, where it was read-only, and the only way to edit one was to expand the
model in the Hierarchy and hunt for the right sub-object.

There is also **◑ Add Material (whole model)**, which is the fast way to give a
whole model a normal map, a roughness, or the retro artefacts above — one
material over every part.

**A node's Material now tints each part instead of replacing it.** Putting a
Material on a model used to collapse every part to one flat colour, which made
it useless for exactly the thing people reach for it for: paying for "make this
model jitter" cost you the model's own colours. Its colour multiplies each
part's, so a fresh Material changes nothing until you dial something in — the
same rule colour already followed against a texture.

*Worth checking after upgrading:* if you put a Material on a multi-part model
and set its colour, that colour is now multiplied by each part's own rather than
replacing it, so those parts will be darker. Per-object overrides are unchanged
— they still replace.

## Shapes lit inside out

Spheres, capsules, planes, cones, cylinders and pyramids were built with their
faces wound the wrong way round, so the engine decided it was looking at their
backs and lit them from behind. What you saw was a surface that stayed dark
where the light was and lit up along its outline — which reads as a strange
material rather than as a bug, and is why it went unnoticed. Cones, cylinders
and pyramids had it on *some* of their faces, so one shape was lit from both
sides at once.

They are all wound correctly now. **Scenes using these shapes will look
different, and better** — if you compensated with an extra light or a raised
ambient, that compensation is now doing double duty.

## From a script

```lua
node:setMaterial{
  shading      = "physical",
  roughness    = 0.35,
  metallic     = 1.0,
  normalMap    = "textures/panel_normal.png",
  occlusionMap = "textures/panel_ao.png",
}

-- one image, three slots (occlusion in red, roughness in green, metallic in blue)
node:setMaterial{ occlusionMap = "textures/orm.png", roughnessMap = "textures/orm.png",
                  metallicMap  = "textures/orm.png" }

-- the retro set
node:setMaterial{ jitter = 120, affineUv = true, vertexLit = true, ditherAlpha = true }

-- and per frame, as cheaply as any other number
mat = node:getcomponent("Material")
mat.roughness = wet and 0.1 or 0.8
```

`""` clears any map slot, the same way it clears `texture`.

## Also in this one

The v0.42 work never went out on its own, so it arrives here. In short:

- **Ctrl+C stops dying halfway through a session.** Copying nodes between
  scenes, and keyframes in the Animating tab, could quietly stop working — along
  with Delete, Ctrl+V, Ctrl+D and F — until you clicked in the right place by
  accident. Clicking any button, checkbox or dropdown was being treated as "the
  user is typing". Only a real text field takes the keyboard now.
- **Tile collision survives closing the project.** Collision shapes, solid
  flags, autotile groups and tags live in the tileset file, and Ctrl+S was not
  writing it. **Check your tilesets after upgrading** — if you drew collision and
  never pressed the Save button inside the ◫ Tiles tab, it was never written.
- **Scenes that refused to open.** One missing line could fail a whole scene,
  and the only report went to a terminal that usually isn't there. Every field
  has a default now, and a file that genuinely can't be read says so in the
  Console, by name.
- **Switching a node off means it everywhere.** A disabled node is no longer
  picked up as the active camera, and `find()`, `findAll()`, `findScript()`,
  `findScripts()`, `findTagged()` and `node:find()` skip switched-off nodes —
  pass `{ scope = "all" }` for the old behaviour. There's an enable switch on the
  Inspector's name row and a search box with the same three scopes in the
  Hierarchy.
- **A colour grade, a lens, and a real depth of field** on the Post Processing
  node: exposure in stops, contrast, saturation, temperature and tint, lift /
  gamma / gain, chromatic aberration and barrel distortion, sharpen, denoise,
  film grain, and depth of field with round bokeh.
- **The image editor holds more than one image** — a tab strip, a close prompt
  that offers Discard, and **Ctrl+V to paste an image from anywhere** (with
  **File ⏵ New from clipboard**).
- **`node:setShaderTexture(slot, ref)`** — point a shader's texture slot at
  another image or a live render target, at runtime.
- **Name your assets when you make them**, instead of getting `NewEffect`.
- **The Map tool is the Model tool** — same tool, honest name. Only the words
  changed.

The full v0.42 notes are in `docs/releases/v0.42.0.md`.

## Nothing to do on upgrade

Every new field starts at the value that changes nothing, and a material that
sets none of them draws exactly as it did — including the file it saves to,
which is byte-identical to a v0.42 one.

The exception is the winding fix above: that changes how the built-in shapes
look, and it is not opt-in, because the old behaviour was wrong.
