# Floptle v0.12.0

Five faults from the Fofighter team, all found in the field, all of the same
family: **the engine knew, and said nothing.** A binding that read wrong, a
migration that undid a deliberate edit, a scene rewired by an unrelated
insertion, a checksum that knew exactly which value diverged and reported none
of it, and a controller a script could not see.

Wire protocol 12 → **13**. Update both ends of a match.

## A gamepad stick could not be scoped to a local player (0043)

`Axis2Binding::Keys` carried `player`. `Stick` did not. So a keyboard layout
could be split between two local players and **an analog stick could not be**.

The obvious two-player map does not do what it looks like:

```ron
Stick( id: Slot(0), x: LeftStickX, y: LeftStickY ),
Stick( id: Slot(1), x: LeftStickX, y: LeftStickY ),
```

`PadId::Slot(n)` names a **device**, not a player. Both sticks contributed to
both players, and since axis bindings resolve largest-magnitude-wins, whichever
stick was pushed harder drove **both characters at once** — while the D-pad
bindings directly beneath it, written in the `Keys` form, scoped correctly. Same
pad, two behaviours.

`Stick` and `Analog` take `player` now, serde-defaulted so every existing map
loads and behaves identically. And a player-scoped `id: Any` means *that
player's own pad, or nothing*, so a second player with no pad reads zero instead
of mirroring the first — the gap the `Any` workaround still had.

## Migrating a project silently undid deliberate input edits (0044)

`merge_missing` decided "missing" with whole-struct equality on `Binding`,
`player` included. That makes three states indistinguishable:

1. the project never had this binding — top it up, the feature's actual purpose
2. the project **deleted** it on purpose
3. the project **kept it but scoped it** to one player

Cases 2 and 3 were silently undone on every version bump. An unscoped binding
serves **every** local slot, so a re-seeded `Key(Space)` meant player one's jump
button also jumped player two. It rewrote `input.ron` to do it, taking the
comments explaining the shape with it — and shipped into two builds before
anyone re-read the file.

Migration now tops up by **name**: a project with an opinion about an action
keeps it, whole. The editor's explicit "add the starter bindings" button still
works at binding granularity, but matches on the *source* rather than the whole
value, so a scoped binding counts as present. And it says what it added, because
this rewrites a file you wrote by hand.

## A scene's parent links were positional indices (0046)

`parent: Some(156)` was an index into the node list. Insert a node ahead of it
and every index below names a different node. The file still loads. Nothing
warns. The scene is simply wired to something else.

It happened to a match HUD: two nodes added ahead of a generated block of
twenty-two, and the timer, round pips, ROUND/FIGHT/K.O. calls and pause menu all
re-parented onto a line of help text inside another panel. An invisible parent
hides its subtree, so none of it was ever drawn, in any mode. It reached players
as **three unrelated bug reports**, every one of them a UI complaint that sends
you reading UI scripts that were correct throughout.

It is worse than a dangling reference because it is always *valid*: node 156
exists, it is just not the node the author meant, and no representation of the
intent survives anywhere in the file.

Nodes now carry a stable `id`, and `parent_id` names one. Both are written —
the positional `parent` stays for older engines — and `parent_id` wins whenever
present, so an insertion cannot move anything. Scenes with no ids load exactly
as before.

Plus the checks that *are* decidable, on every scene load: a `parent_id` nothing
carries, an out-of-range index, a self-parent, a cycle, two nodes claiming one
id — each named by node. And the lint for the shape that made this invisible
rather than obviously broken: **a UI element whose parent chain can never be
visible is reported**, naming both the element and what is hiding it.

## A desync named nothing (0045)

A cross-platform match (Linux host, Windows joiner) voided itself within seconds,
every time, for days. The cause was one Lua number:

```lua
st.visYaw = st.visYaw + diff * (1 - math.exp(-18 * dt))
```

`math.exp` is library code and is not required to agree between glibc and
Windows' UCRT. One ULP, every tick. The value is *how far the model has turned* —
presentation, which neither simulation could feel. Both machines were running
the same fight, correctly, and the checksum was still right to fire.

Finding that took a day, because this was everything the game was told:

```lua
net.on("desync", function() ... end)   -- no payload at all
```

Three changes:

**The desync names the value.** Once a mismatch is declared — and only then, so
a healthy session pays nothing — every peer publishes a labelled breakdown of
the offending tick, one hash per body and per snapshot key. The host folds them
and prints what actually differs:

```
⚖ tick 4127 — Player2/fighterController/visYaw differs (peer 0: …a3f1, peer 1: …a3f2)
```

The handler now receives `{ tick, node }`.

**`snapshot()` has a cosmetic half.** A correction must put back everything a
replay needs; two peers must agree about rather less. Those are different sets,
and `snapshot()` was all-or-nothing, so presentation had nowhere to go but into
the checksum. It may now return a **second** value — restored on rollback, never
hashed. A one-value `snapshot()` is unchanged.

**The portability rule is written down.** `+ - * /` and `sqrt` are pinned by
IEEE-754; `exp`, `log`, `sin`, `cos`, `tan`, the inverse trig and `pow` are
library code and are not. A gameplay author has no reason to know that, and the
failure is a match that ends itself on a machine they do not own.

## A script could not see a gamepad (0047)

The Lua input API was entirely action-shaped. Every call answers the *resolved*
question — did this player press Light. None could answer the one underneath it:
**is there a controller here at all.**

So "the pad was never enumerated", "it went into a slot the map doesn't bind",
"the window hasn't got focus" and "something downstream ate it" all reach the
developer as one sentence — *controllers don't work* — which is not actionable.
That cost this project three round trips across two playtests with players in
another country.

```lua
for _, p in ipairs(input.pads()) do
  log(("pad %d: %s%s"):format(p.index, p.name, p.connected and "" or " (gone)"))
end
```

`input.pads()`, `input.padCount()`, and a raw read-through — `input.padButton(1,
"South")` and `input.padAxis(1, "LeftStickX")` — that bypasses the action map
entirely. That last part is the difference between "your pad works, your
bindings are wrong" and "your pad is not here", and only the raw read can tell
them apart. A game can put it on a controls screen and let the player diagnose
it.
