# Test models

Real exporter output, not hand-written files. That is the point of them: the
things that break a model converter — a unit declared one way and written
another, an ASCII FBX from 2013, a mesh split across two materials — are
artefacts of what real exporters actually do, and a fixture written by hand to
match the parser would pin nothing.

Taken from the [ufbx](https://github.com/ufbx/ufbx) project's `data/`
directory, which is covered by that repository's LICENSE: MIT **or** the
Unlicense (public domain), at the user's choice. Copyright (c) 2020 Samuli
Raivio. They are Blender's own export of its default primitives.

| File | Why it is here |
|---|---|
| `blender_272_cube_7400_binary.fbx` | Modern binary FBX. A 2×2×2 cube, so the converted size and volume are exactly checkable. |
| `blender_279_ball_7400_binary.fbx` | Binary FBX in centimetres, split across two materials. |
| `blender_279_ball_6100_ascii.fbx` | **The unit trap.** Blender's legacy ASCII exporter declares centimetres and writes metres. The same ball as above, so the two must convert to the same size. |
| `blender_279_ball_0_obj.obj` + `.mtl` | The same ball again, as OBJ. Three formats, one model — the cross-check that catches a units or winding change in any single path. |
| `blender_279_bone_radius_7400_binary.fbx` | Bones and no meshes. Must fail with "there is no geometry", not write an empty `.glb`. |
| `blender340_tangent_sign_7400_binary.fbx` | Has texture coordinates, which nothing else here does — a model whose UVs are lost converts to something that cannot be textured. |
| `blender_279_color_sets_7400_binary.fbx` | Per-vertex colour, which a converter written for game props drops without noticing. |

STL, PLY and loose-glTF fixtures are **generated by the tests** rather than
stored — those formats are simple enough to write exactly, so the test can state
the geometry it expects instead of asserting against a file nobody can read.
